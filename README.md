# أنظمة الأفق — الحجز المسبق

نسخة DEMO كاملة بخمس خطوات، مصممة للعربية والهاتف. لا تعدّل Google Form ولا تتصل بـ Google Sheets ولا ترسل بيانات إلى أي خدمة. الرسومات والخيارات تصورية للعرض، وليست تأكيداً للمواصفات التجارية أو توفر الأجهزة.

## التقنية والتشغيل

HTML semantic، CSS responsive، JavaScript ES Modules، Node.js 22+. بدون اعتماديات تشغيل أو تنزيل خطوط خارجية.

```sh
npm run dev
# http://localhost:4173
npm test
npm run build
npm run preview
```

البناء ينسخ الموارد إلى `dist/` ويضبط روابط Open Graph. لا تحتاج `npm install` للتشغيل والبناء. ملف `scripts/assets.mjs` اختياري لإعادة توليد الصور ويتطلب sharp؛ جميع الصور الناتجة موجودة بالفعل في المستودع.

## Cloudflare Pages

- اختر المستودع `storeqn/alofuq-booking-demo` وفرع `main`.
- Framework preset: None.
- Build command: `npm run build`
- Build output directory: `dist`
- Root directory: جذر المستودع (اتركه فارغاً).
- متغير `NODE_VERSION`: `22`.
- متغير `SITE_URL`: رابط النشر النهائي الكامل، مثلاً `https://alofuq-booking-demo.pages.dev`، يمكن أن يتضمن مسار مشروع GitHub Pages. عند غيابه يستخدم البناء `CF_PAGES_URL` ثم رابط المشروع الافتراضي.
- صفحة واحدة بلا Router؛ لا توجد مسارات فرعية تحتاج redirects. روابط الخطوات تستخدم anchors.
- بعد النشر تأكد من معاينة صورة المشاركة. تغيير الدومين يتطلب تحديث `SITE_URL` وإعادة البناء.

## أماكن التعديل

- الأجهزة والسعات والألوان والحملات: `src/data/catalog.js`.
- النصوص الرئيسية واسم الجهة والتواصل: `index.html`؛ الشعار المصغر وصورة المشاركة في `public/assets/`.
- اللون الأساسي والتصميم: متغير `--accent` في `src/styles/main.css`؛ theme color في `index.html` و`public/manifest.webmanifest`.
- مكونات الخطوات والملخص: `src/components/wizard.js`.
- إدارة الحالة والتقدم: `src/app.js`.
- التحقق من الاسم والبريد وأرقام العراق المحلية والدولية: `src/utils/validation.js`.
- الإرسال: `src/services/bookingService.js`.

بيانات المنتجات مستقلة عن الواجهة. تتضمن الحمولة `campaignId` لتسهيل إضافة الحملات؛ عند إضافة حملة فعلية، أضف بياناتها ومنطق اختيار الحملة والمنتجات المرتبطة بها. الخيارات الحالية موحدة بين الجهازين لأغراض العرض.

## الخصوصية

الجهاز والسعة واللون فقط في `sessionStorage`، بدون الاسم أو الهاتف أو البريد. المعلومات الشخصية تبقى في الذاكرة خلال تجربة الحجز وتُمسح بعد النجاح أو بدء حجز جديد. تحديث الصفحة يمسح المعلومات الشخصية. لا analytics ولا tracking ولا طلبات خارجية. يمنع CSP الاتصال بالخدمات الخارجية في نسخة العرض.

## الربط الحقيقي لاحقاً

بعد موافقة العميل نحتاج صلاحية من مالك نظام Google الحالي، ومعرفة أسماء الأعمدة أو معرفات حقول النموذج والملف المرتبط، وقواعد الحجز والتوفر والموافقة على الخصوصية. لا تفترض أن إنشاء Sheet جديد مطلوب: الهدف هو الكتابة في الملف الحالي عبر تكامل مصرح به.

استبدل محول `submitBooking()` بـ API آمن (مثلاً Cloudflare Pages Function يستدعي Google Apps Script) مع تحقق على الخادم، rate limiting، idempotency ومنع التكرار، CORS صحيح، معالجة الأخطاء، ومعرف حجز من الخادم. اربط حقول الحمولة بأعمدة الملف الحالي. ضع الأسرار في بيئة الخادم فقط. حدّث CSP من `connect-src 'none'` إلى `'self'` إذا استخدمت endpoint من نفس الأصل. اختبر الربط ببيانات اختبار مصرح بها قبل الإطلاق. لا تزيل ملاحظات Demo إلا بعد تفعيل النظام الحقيقي.

## PWA

Manifest وأيقونات جاهزة كأساس PWA. لا Service Worker حالياً لتجنب بقاء نسخة قديمة أو تخزين بيانات شخصية. يمكن إضافة caching للأصول فقط لاحقاً بعد تحديد سياسة التحديث. على iPhone يمكن استخدام المشاركة ثم «إضافة إلى الشاشة الرئيسية»؛ التثبيت التلقائي ليس مضموناً في جميع المتصفحات.

## الاختبارات

`npm test` يفحص أرقام العراق والتحقق من المعلومات ورفض البيانات المعدلة وتميز أرقام الحجز وعدم استخدام الشبكة. الاختبار التفاعلي `tests/browser-check.mjs` يحتاج Playwright مثبتاً وChromium: شغّل preview ثم `node tests/browser-check.mjs`. يغطي الرجوع، الخيارات، validation، النجاح، الضغط المكرر، عدم تسريب البيانات، الأخطاء والأصول ومقاسات الهاتف وسطح المكتب. اللقطات والتقرير في `.test-artifacts/`، ولا تُرفع إلى Git.


## معاينة GitHub Pages

يدعم المشروع النشر من جذر فرع `main` عبر Settings → Pages → Deploy from a branch → main → / (root). تعمل روابط CSS وJavaScript والصور النسبية تحت `/alofuq-booking-demo/` وكذلك على جذر Cloudflare. الموارد موجودة في `public/` في المصدر ومخرجات البناء معاً. عند استخدام بناء GitHub Pages اضبط `SITE_URL=https://storeqn.github.io/alofuq-booking-demo` لضبط بيانات مشاركة الرابط أيضاً. لا تستخدم مجلد `public` وحده كمجلد نشر؛ نقطة الدخول `index.html` في جذر المشروع.
